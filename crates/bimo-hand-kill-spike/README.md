# bimo-hand-kill-spike — سبايك قتل اليد (الدورة 39، قياس فقط)

## لماذا هذا السبايك؟

فشل الدليلان 8.1 و8.2 في الاختبار الذاتي لليد (الدورة 38، فرع unit3-part4-c38، رأس نتائج السبايك 3a92c73): بعد TerminateJobObject بقيت العملية 4568 حية، وكان stop_ms هو 5040 و5047 — فوق حد 5000ms. التشخيص: التثبيت الحقيقي يجري في خدمة Windows Installer (عملية msiexec.exe /V بحساب LocalSystem، الأب services.exe، الجلسة 0)، وليس في عميل msiexec.exe الموجود داخل الـjob. TerminateJobObject يقتل أعضاء الـjob فقط، فالخدمة لا تموت به أبدا.

هذا السبايك يقيس — لا يدمج ولا يفتح PR — ثلاثة أسئلة:

1. هل يعيد سيناريو 8.1 نفسه إنتاج الفشل، ومن هو الناجي بالضبط؟
2. هل يقتل قتل الشجرة عبر PPID الشجرة كاملة؟ وهل تبقى عملية الخدمة؟
3. هل يلغي MsiInstallProduct مع معالج واجهة خارجي يعيد IDCANCEL التثبيت إلغاء معامليا (المنتج غائب، وميوتكس Global_MSI_Execute حر، والخدمة خاملة)؟

## المراحل

- المرحلة 0 — إعادة إنتاج 8.1 بالهوية: VLC 3.0.20 win64 MSI، مشرف مرتفع، job بلا breakaway، القتل عند 40% من مدة التثبيت المعايرة، بالطريقة القديمة (TerminateJobObject فقط). يسجل هوية كل ناج: مسار الـexe، PPID، رقم الجلسة، المستخدم (SYSTEM أو مستخدم)، وIsProcessInJob. حكم pass هنا يعني أن الفشل أعيد إنتاجه (ناج باق وstop_ms فوق 5000ms).
- المرحلة 1 — نفس السيناريو بقتل الشجرة عبر PPID: لقطة Toolhelp، مجموعة الأحفاد الكاملة، TerminateProcess من الأعمق للأعلى، ثم TerminateJobObject كمسح ثان، ثم إعادة تعداد ومحاولة واحدة للناجين عبر PID. توقيت كل مرحلة (تعاوني / قسري / تحقق / إعادة محاولة) مسجل على حدة، لأن stop_ms الموحد (~5.04s) في الدورة 38 كان على الأرجح حلقة تحقق تعمل حتى نهاية الميزانية، لا انتظارا ثابتا.
- المرحلة 2 — إلغاء MSI عبر الـAPI: MsiInstallProduct مع معالج UI خارجي يعيد IDCANCEL عند إشارة الإيقاف. النجاح يتطلب: رمز الإرجاع 1602 (ERROR_INSTALL_USEREXIT)، والمنتج غائب، وميوتكس Global_MSI_Execute حر، والخدمة خاملة. عملية msiexec.exe /V الخاملة المتبقية هي مضيف الخدمة نفسه، لا تثبيتا لمنتجنا، وتُحسب عملية خدمة لمنتجنا فقط ما دام الميوتكس محجوزا.
- المرحلة 3 — إعادة سيناريو 8.2: ملف 1GB يُنسخ ببطء (ثنائي نفسه في وضع --slow-copy)، والقتل عند تجاوز التقدم 25%، مع قتل الشجرة عبر PPID.

## التشغيل

    cargo build --release --target x86_64-pc-windows-msvc -p bimo-hand-kill-spike
    .\target\x86_64-pc-windows-msvc\release\bimo-hand-kill-spike.exe --out hand-kill-spike.json

رمز الخروج 0 يعني أن JSON كُتب، مهما كانت أحكام المراحل — السبايك يقيس، لا يبوّب. رمز 1 يعني أن JSON نفسه لم يُكتب. أرقام العداء موسومة runner_note: does not prove device performance.

## الملفات

- src/main.rs — نقطة الدخول (--out، ووضع --slow-copy المساعد)
- src/win32.rs — استدعاءات Win32 الخام: Job، Toolhelp، هوية العمليات
- src/msi.rs — واجهة Windows Installer: MsiInstallProduct، IDCANCEL
- src/stop.rs — تسلسلا الإيقاف مع توقيت كل مرحلة
- src/stages.rs — التنزيل والمعايرة والمرحلتان 0 و1
- src/stages2.rs — المرحلتان 2 و3 والتشغيل الكامل

الكريت مستقل ولا يعتمد على كريت windows (كل استدعاءات Win32 معلنة بصيغها الكلاسيكية في win32.rs وmsi.rs)، ويُبنى أيضا على غير Windows حيث يكتب JSON بحكم inconclusive.
